# Google Workspace 串接指南

系統以 Google Apps Script Web App 作為前端與 Google Workspace 的橋接層：把班級資料同步到 Google Sheets、在 Drive 建立與還原 JSON 備份、上傳教學檔案，並用 Google Docs 產生班級或個別學生報告。部署後也可以直接嵌入 Google Sites。

> **對應版本**：Apps Script `SCRIPT_VERSION = 2.5.0`，資料 schema v2。
> 前端會在診斷時比對版本；若顯示「部署中的版本為 2.4.x」，代表 `Code.gs` 改過但沒有重新部署。

---

## 1. 建立 Apps Script 橋接器

1. 用**預計長期保存教學資料的 Google 帳號**登入（建議是學校 Workspace 帳號，不要用個人帳號）。
2. 開啟 [Google Apps Script](https://script.google.com/) →「新專案」，把專案命名為「自然課堂中控站橋接器」。
3. 刪除編輯器內預設的 `myFunction`，把 `integrations/apps-script/Code.gs` 的**全部內容**貼進去，存檔。
4. 上方函式選單選 `setupNatureHub` → 按「執行」。
5. 第一次執行會跳出授權畫面：「查看權限」→ 選擇同一個帳號 → 若出現「Google 尚未驗證這個應用程式」，點「進階」→「前往 自然課堂中控站橋接器（不安全）」→「允許」。
   這是自己寫的指令碼未經 Google 商店審核的正常提示。
6. 執行紀錄若顯示完成，Drive 會出現：
   - 試算表「自然課堂中控站－資料庫」（12 個分頁）
   - 資料夾「自然課堂中控站－教學資料」

### 需要授權的範圍

| 範圍 | 用途 |
| --- | --- |
| Google Sheets | 建立與更新資料庫分頁 |
| Google Drive | 建立資料夾、寫入 JSON 備份、上傳教學檔案 |
| Google Docs | 產生班級與個別學生學習報告 |
| 外部要求／指令碼屬性 | 記住試算表與資料夾 ID |

---

## 2. 部署 Web App

1. 右上角「部署」→「新增部署作業」。
2. 齒輪圖示 → 類型選「網頁應用程式」。
3. 設定：
   - **說明**：填版本備註，例如 `v2.3.0 自動備份`
   - **執行身分**：選「我（你的帳號）」。這樣所有老師都寫入同一份資料庫，也不需要每位使用者各自授權。
   - **誰可以存取**：學校網域環境選「＜學校網域＞內的任何人」；若管理員未開放，才退而選「知道連結的任何人」。
     **不要選「任何人（包含匿名）」以外還把網址公開張貼**——這個網址等同資料庫的寫入權杖。
4. 部署完成後複製 `/exec` 結尾的網址（不是 `/dev`）。
5. 回到系統「串接與設定」→ 貼上網址 → 按「儲存並測試」。

> ⚠️ **每次修改 `Code.gs` 後**都要「部署」→「管理部署作業」→ 鉛筆圖示 → 版本選「新版本」→「部署」。
> 只按存檔不會更新線上版本，前端診斷會直接指出版本落後。

---

## 3. 驗收流程（照順序做完才算串接完成）

在「串接與設定 → 連線診斷」依序執行：

### 第 1 步：儲存並測試
確認回報「Google 串接設定成功」，且版本檢查顯示 `2.1.0（與前端相符）`。

### 第 2 步：執行唯讀診斷
不寫入任何資料，逐項檢查：

| 檢查項目 | 通過條件 |
| --- | --- |
| Apps Script 版本 | 與前端預期版本相符 |
| Google Sheets 資料庫 | 能開啟、分頁數正確 |
| 分頁 Classes / Lessons / Students / Attendance / AttendanceLog / Rewards / RewardMenu / Assessments / Scores / Observations / Resources / Metadata | 標題列欄位與定義完全一致 |
| 每日自動備份觸發器 | 已安裝（未安裝時會指示你執行 `installDailyBackup`） |
| Google Drive 資料夾 | 能開啟並列出檔案數 |
| 最新 Drive 備份 | 有備份檔並顯示時間與大小（首次執行前會是未通過，屬正常） |

若分頁欄位不符（例如沿用舊版含 `name` 欄的 Students），到試算表把該分頁整個刪除，回 Apps Script 重跑一次 `setupNatureHub`。

### 第 3 步：執行寫入測試
實際驗證三種寫入權限，測試產物驗證後**自動刪除**：

| 步驟 | 驗證內容 |
| --- | --- |
| Sheets 寫入與讀回 | 建立 `_SelfTest` 暫存分頁，寫入時間戳並讀回比對，再刪除分頁 |
| Drive 檔案建立與讀回 | 在資料夾建立小型 txt、讀回內容比對，再移到垃圾桶 |
| Google Docs 建立與搬移 | 建立測試文件、搬進資料夾，再移到垃圾桶 |

勾選「保留寫入測試產物」可讓檔案留在 Drive 供人工檢視（需自行刪除）。

### 第 4 步：立即同步
按「立即同步」，然後：
- 開啟試算表，確認 Classes 與 Lessons 各有 6 列、Students 有 180 列。
- 確認 `Lessons` 的六列課程單元彼此獨立（各班主題可不同）。
- **確認 Students 分頁沒有任何真實姓名欄位**（欄位應為 `id, classId, number, seat, tags, note, active, createdAt`）。
- 確認 Drive 資料夾出現 `backup-YYYYMMDD-HHMMSS.json`。

### 第 5 步：從 Google 還原
按「從 Google 還原」，確認資料回填且班級切換器仍是 6 班。（會覆蓋本機資料，建議先下載一份 JSON 備份。）

### 第 6 步：Docs 報告
到「統計報表」分別建立班級報告與個別學生報告，確認：
- 文件建立在「自然課堂中控站－教學資料」資料夾內。
- 內容只出現學生編號（如 `4201`），沒有真實姓名。

### 第 7 步：Drive 檔案上傳
到「教學資料庫」上傳一個小檔案並按「上傳 Drive」，確認 Drive 出現該檔案。單檔上限 8 MB。

### 第 8 步：嵌入 Google Sites
在 Google Sites 編輯畫面選「插入」→「嵌入」→「網址」，貼上 <https://prayer168.github.io/nature-classroom-hub/>。
注意：資料存在**瀏覽器本機**，嵌入 Sites 只是換一個入口，不會讓資料跟著 Sites 走。

診斷結果可按「複製診斷結果」取得純文字，貼上來回報問題最快。

## 3.5 安裝每日自動備份

部署完成後，在 Apps Script 編輯器的函式選單選 **`installDailyBackup`** 按「執行」一次即可。

- 由 Google 在伺服器端每天約 **22:00** 執行，**不需要教師開著網頁**。
- 備份檔命名為 `backup-YYYYMMDD-HHMMSS-auto.json`，存在「自然課堂中控站－教學資料」資料夾。
- 最多保留 **30 份**，超過的最舊備份自動移到垃圾桶（手動同步時也會一併清理）。
- 重複執行不會裝出第二個觸發器；要停用請執行 `removeDailyBackup`。

> ⚠️ 自動備份是把 **Google Sheets 目前的內容**導回 JSON，所以備份的是「已同步到雲端的資料」。
> 老師在瀏覽器改了但沒按「立即同步」的資料**不會**進到自動備份。習慣上每次上完課按一次「立即同步」，自動備份才有意義。

## 4. 資料如何落地

「立即同步」是**整批覆蓋**：每個分頁先清空再重寫，並在 Drive 留一份完整 JSON 備份。

| 分頁 | 內容 |
| --- | --- |
| Classes | 6 個班級的代碼、年級、科目、學年 |
| Lessons | 各班獨立的課程單元、課次、今日任務與開始時間 |
| AttendanceLog | 補改過去出席的稽核紀錄：修改時間、日期、學生與前後狀態 |
| TransferLog | 轉班紀錄：學生、原班級、新班級、前後編號與時間 |
| Students | 學生編號、座號、班級、標籤、備註、`deletedAt`（回收筒）（**不含姓名**） |
| Attendance | 逐日逐生出席狀態 |
| Rewards / RewardMenu | 點數紀錄與獎品目錄 |
| Assessments / Scores | 評量定義與各生得分；`Scores.status` 為 `absent` 代表缺考 |
| Observations | 教師觀察紀錄 |
| Resources | 教學資源清單（連結與檔案中繼資料），`grade` 標示通用／四年級／六年級 |
| Metadata | 同步時間、schema 版本、班級與學生數 |

伺服器端會再做一次去識別化：即使前端誤送 `name`、`fullName`、`realName`，寫入 Sheets／Drive 備份／Docs 前都會剝除。

## 5. 疑難排解

| 症狀 | 原因與處理 |
| --- | --- |
| 「連線測試被導向 Google 登入頁」 | 瀏覽器沒登入有權限的帳號，或存取權限設得太窄。先登入正確帳號，或放寬「誰可以存取」。 |
| 「HTTP 403 被拒絕」 | 部署的存取權限不含目前帳號。到「管理部署作業」調整。 |
| 「HTTP 404」 | `/exec` 網址失效，多半是刪掉舊部署。重新部署並更新網址。 |
| 「回傳的是網頁而非資料」 | 貼到 `/dev` 網址，或部署類型不是網頁應用程式。 |
| 「遭遇授權錯誤」 | 從未手動執行過 `setupNatureHub`。回 Apps Script 執行一次並完成授權。 |
| 「部署中的版本為 2.0.x」 | `Code.gs` 已更新但沒建立新版本部署。 |
| 「連線逾時」 | 資料量大時 Apps Script 可能超過 30 秒。同步逾時上限已放寬到 60 秒；仍逾時請減少歷史出席資料。 |
| 「另一項同步正在進行中」 | 兩台裝置同時同步。等 30 秒後重試。 |
| 分頁欄位不符 | 舊版分頁結構。刪掉該分頁後重跑 `setupNatureHub`。 |

## 6. 資安注意事項

- 不要把 Google OAuth token、服務帳戶私鑰或 API 金鑰放進前端檔案。
- **Web App 網址等同寫入權杖**：不要張貼在公開網頁、簡報或家長群組。
- 系統只使用學生編號，不保存真實姓名；出席、備註與成績仍屬敏感教育資料，請限制在學校 Workspace 網域並遵循校內個資保存規範。
- 共用電腦使用完畢後，請下載備份並清除瀏覽器站台資料。
- 「執行身分＝我」代表任何能開啟該網址的人都能以你的身分寫入資料庫。若要提供多校、多教師與家長登入，下一階段應改用正式身分驗證與資料庫列級權限，不應把 Apps Script 公開成「任何人」可存取。

## 7. 目前限制（尚未實作）

- 沒有雙向同步與衝突處理：同步是本機覆蓋雲端，還原是雲端覆蓋本機。
- 自動備份只涵蓋已同步到雲端的資料；本機未同步的變更不在其中。
- 沒有登入與角色權限，任何取得網址的人皆可寫入。
- 評量定義與獎品目錄為六班共用（刻意設計：同一套評量標準較公平、獎品由教師實體準備）。課程單元已依班級獨立，資源庫已依年級分類。
